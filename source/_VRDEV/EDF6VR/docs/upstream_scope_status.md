# 本家3.0.1のスコープ実装と参考資料の位置付け

## 確認した更新

2026-10-01の準備中に本家の最新状態を取得したところ、
[EDF6VR 3.0.1](https://github.com/momotori01/EARTH-DEFENSE-FORCE-6-VR-MOD/releases/tag/EDF6VR-3.0.1)
が同日19:33 JSTに公開されていました。スコープ機能は3.0.0から追加されています。
確認した`main`のコミットは`898d92515a0c6bf9cf4d8833f49c0394593b51cd`です。

公式の[3.0.1リリースノート](https://github.com/momotori01/EARTH-DEFENSE-FORCE-6-VR-MOD/blob/898d92515a0c6bf9cf4d8833f49c0394593b51cd/source/_VRDEV/EDF6VR/packaging/RELEASE_NOTES_3.0.1.md)
では、ズーム時に武器側のスコープ・画面内を拡大し、周囲は等倍に保つことと、
Native／Digital／Offの切り替えが案内されています。
レティクルの傾きと、歩行・ローリング時のレーザー位置についての修正も記載されています。

本資料は公開説明とソースの確認結果です。**3.0.1をゲームへ導入しておらず、
ヘッドセットでの見え方、性能、各武器の使用結果を確認したわけではありません。**

## 旧版の参考実装との違い

このDraft PRの基準は、EDF6VR 2.1.8（`b84c7f2`）です。
本家3.0.1へそのままマージする前提ではありません。

| 項目 | この参考実装 | 本家3.0.1のソースで確認した内容 |
|---|---|---|
| 倍率・起動条件 | SVU01の同一フレームの姿勢があると固定2倍を合成。ゲーム標準ズームは別に残る | ゲーム標準ズームが有効な間、その倍率を使用。スコープ表示中は周囲の全体ズームを抑制 |
| 画像の作り方 | 各目の画面上で開口部中心からの距離を半分にしてサンプリング | Nativeは追加のスコープ用描画、Digitalは各目の既存の画像を使用 |
| 描画と照準 | 画面上の楕円。光学的な覗く位置の扱いは未実装 | 武器上の面とカメラ・射線を扱う`ScopeLensSpec`、`ScopeView`、`ScopeDrawInput`を使用 |
| 武器の識別 | ロード済みリソース名がSVU01かを判定 | モデルのノード名と複数のレンズ・画面定義を使用 |
| 対象形状 | SVU01の円形開口部。MMF01は別途の幾何加工例のみ | 円形・矩形・マーカー銃の画面・ホログラム表示などを用意 |
| 変更済みゲームデータ | 手元の元データからRABを生成して手動配置 | 調べたスコープ合成コードは武器上の面に画像を描画。今回のレンズ除去用RABを前提にしていない |
| 設定 | スコープ専用の有効・無効設定なし | `[VR] ScopeMode`：0 Off、1 Native、2 Digital。`ScopeLensScale`も用意 |

コード上の比較対象：

- [scope.h](https://github.com/momotori01/EARTH-DEFENSE-FORCE-6-VR-MOD/blob/898d92515a0c6bf9cf4d8833f49c0394593b51cd/source/_VRDEV/EDF6VR/src/scope.h)
- [scope.cpp](https://github.com/momotori01/EARTH-DEFENSE-FORCE-6-VR-MOD/blob/898d92515a0c6bf9cf4d8833f49c0394593b51cd/source/_VRDEV/EDF6VR/src/scope.cpp)
- [scope_draw.h](https://github.com/momotori01/EARTH-DEFENSE-FORCE-6-VR-MOD/blob/898d92515a0c6bf9cf4d8833f49c0394593b51cd/source/_VRDEV/EDF6VR/src/scope_draw.h)
- [plugin.cpp](https://github.com/momotori01/EARTH-DEFENSE-FORCE-6-VR-MOD/blob/898d92515a0c6bf9cf4d8833f49c0394593b51cd/source/_VRDEV/EDF6VR/src/plugin.cpp)の`ScopeLensFor`、`UpdateScopeView`

Digitalには追加のシーン描画がありませんが、実際の負荷は未測定です。
今回の軽さ優先の試作と比較する際は、NativeとDigitalの設定を区別する必要があります。

## 武器対応についての確認範囲

本家の定義にはMMF01、SVU01、ライサンダー系、ドゥンケル、フラウンダー、NP系、
イーグル、ファング、KFF71Sのモデルに対応するノード名が含まれています。
定義のコメントでは、フラウンダーとペネトレイター系の共有行も説明されています。
ノード名で識別するため、今回のRAB名・MDB名の対応表と単純な文字列比較だけでは
実際の武器対応を判定できません。

`s_sniper_613_heavy01`（プラネット系）は同名の明示的なレンズ行を見つけていません。
コードには追跡済みの武器でレンズ行が見つからない場合のホログラム表示がありますが、
プラネット系でどの表示になるかは実機未確認です。これは未対応の断定ではありません。

## 開発者へ共有する内容

- スコープ内だけを拡大するという主な要望は、本家で既に機能として案内されています。
  旧ドラフトをそのまま新規Feature Requestとして投稿することは避け、
  新版での使用結果と残っている希望を確認した上で提案内容を整理するのが適切です。
- 参考コードを求められていることには、2.1.8を基準にしたDNMの例として応えられます。
  マージ可能な3.0.1向け差分として扱うものではありません。
- 合成のテスト設計（縦横の倍率、中央からずらした開口部、開口部外の画素保持、
  意図的に誤った実装で失敗すること）と、武器モデルの対応表を補足情報として共有できます。
- MMF01の42三角形の加工例は幾何データの調査例です。本家への導入に必要な加工という
  意味ではなく、実機未確認であることも併記します。

固定2倍の常時表示と、ゲームのズーム操作を使う新版の動作は同一ではありません。
この違いが残る要望になるかは、使用結果を確認して判断する必要があります。
